# Repository Engineering Instructions

Treat Foundation, accepted ADRs, and accepted governance as authority. Treat downstream draft specs as proposals requiring validation.

Always:

- discover existing artifacts before asking or creating
- read in `governance/READING_ORDER.md` order
- apply deterministic rules before AI inference
- preserve provenance, evidence, uncertainty, and Workspace context
- use interfaces across ownership boundaries
- create Knowledge Candidates from observations
- report missing authority or evidence as blocked

Never:

- invent business rules or expected results
- use conversation history as authoritative knowledge
- store raw DOM as product meaning
- let plugins own core policy
- bypass Workspace authorization
- promote AI output directly to accepted knowledge
- set `accepted` without review and quality-gate evidence
