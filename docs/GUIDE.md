# QA Intelligence — Install & Usage Guide

Derived documentation. Authoritative sources: `README.md`, `hosts/README.md`,
`api/README.md`, `src/mcp/dev-entrypoint.ts`, `src/mcp/remote-dev-entrypoint.ts`,
ADR-016, ADR-020, GOV-012. Generated by manual review of those sources
(2026-08-07). If this file and a source above disagree, the source wins.

## 0. Status — read this first

QA Intelligence has **no production API and no UI**. `api/README.md` says
implementation has not started. The only thing you can run today is a
**development-only MCP server** exposing one tool,
`assess_requirement_quality`, against one seeded requirement
(`REQ-DEMO-001`). Auth is a fixture verifier, not real OIDC. Knowledge Store
is an in-memory seed. This guide only documents what actually runs.

There are two transports:

- **Local `stdio`** (`dev-entrypoint.ts`) — one process per Workspace, used by
  Claude Code / Codex / Cursor as a local MCP server.
- **Remote Streamable HTTP** (`remote-dev-entrypoint.ts`) — same runtime,
  reachable over `http://127.0.0.1:8787/mcp`, with real signed OIDC tokens
  from a self-hosted dev JWKS (still non-production membership).

## 1. Prerequisites

- Node.js `>=24 <25` (repo pins `24` in `.nvmrc`; `node --version` should
  print `v24.x`)
- npm (ships with Node)
- Python 3 (only needed for `npm run validate:repository`)

## 2. Install

```sh
git clone <repo-url> QA-Intelligence
cd QA-Intelligence
npm install
npm run build          # compiles src/ -> dist/, required before any MCP entrypoint runs
```

Optional sanity checks:

```sh
npm run typecheck
npm test               # builds then runs dist/tests/**/*.test.js
npm run validate       # repository governance + schemas + typecheck + test + audit
```

## 3. Usage — local `stdio` MCP server (per host)

All three hosts point at the same compiled entrypoint:
`dist/src/mcp/dev-entrypoint.js`. Run `npm run build` first — the packages
launch compiled JS, not the TypeScript source.

### 3.1 Claude Code

Config lives at `hosts/claude-code/.claude-plugin/plugin.json` and is
already relative to that directory:

```json
{
  "mcpServers": {
    "qa-intelligence": {
      "command": "node",
      "args": ["../../../dist/src/mcp/dev-entrypoint.js"],
      "env": { "QA_INTELLIGENCE_DEV_WORKSPACE_ID": "workspace-claude-code-dev" }
    }
  }
}
```

Install as a Claude Code plugin from the repo (path form), then in a
Claude Code session confirm the server connected and the tool is visible
(e.g. `/mcp` or your host's server-list command) before calling it.

### 3.2 Codex

`hosts/codex/.codex-plugin/plugin.json` uses the same relative path under
a `mcp.servers` key instead of `mcpServers` — install per Codex's plugin
mechanism, same compiled entrypoint.

### 3.3 Cursor

Copy `hosts/cursor/mcp.json.example` into your Cursor MCP settings and
replace the placeholder with an **absolute** path (Cursor config is not
relative to the repo):

```json
{
  "mcpServers": {
    "qa-intelligence": {
      "command": "node",
      "args": ["/absolute/path/to/QA-Intelligence/dist/src/mcp/dev-entrypoint.js"],
      "env": { "QA_INTELLIGENCE_DEV_WORKSPACE_ID": "workspace-cursor-dev" }
    }
  }
}
```

### 3.4 Manual smoke test (any host, or raw stdio)

You can run the server directly to confirm it starts:

```sh
QA_INTELLIGENCE_DEV_WORKSPACE_ID=workspace-manual-dev node dist/src/mcp/dev-entrypoint.js
```

It speaks MCP `2025-06-18` over stdio — it will sit waiting for JSON-RPC
frames on stdin. Use your host's tool-call UI rather than hand-writing
frames.

## 4. The one tool: `assess_requirement_quality`

- **Purpose**: run the Requirement Review Agent / Assess Requirement
  Quality Skill (SPEC-203 + SPEC-202 rule sets) through the real Agent
  Runtime and Rule Engine.
- **Input schema**:
  ```json
  { "requirement_ref": "REQ-DEMO-001@1.0.0" }
  ```
  `requirement_ref` is required as a matter of the declared schema, but the
  entrypoint's `buildInput` defaults it to `REQ-DEMO-001@1.0.0` if omitted.
  Only `REQ-DEMO-001` resolves — the Knowledge Store / requirement resolver
  is an in-memory seed with exactly that one record.
- **Consequence class**: `advisory` (SPEC-508) — result is informational,
  not a gate.
- **Budgets**: `max_steps: 8`, `max_duration_seconds: 120`,
  `max_tool_calls: 10`, `max_retries: 1`.

### 4.1 Example — from a host chat (Claude Code / Cursor / Codex)

Once the MCP server is connected, ask the host to call the tool, e.g.:

> Call `assess_requirement_quality` with `requirement_ref: "REQ-DEMO-001@1.0.0"`.

Expected shape of the result: an assessment record referencing
`REQ-DEMO-001`, findings from both rule engines
(`RequirementQualityRuleEngine`, `RequirementIntelligenceRuleEngine`), and
`resolved_versions` metadata (`agent`, `skill`, `prompt`, `rule_set`,
`knowledge_snapshot`, `policy`, `input_schema`, `output_schema`) as set in
`dev-entrypoint.ts`.

### 4.2 Example — requirement not in the seed

```json
{ "requirement_ref": "REQ-NOT-REAL@1.0.0" }
```

Expect a resolution failure — `InMemoryRequirementResolver` only knows
`REQ-DEMO-001`. This is expected dev-seed behavior, not a bug.

### 4.3 Session memory

The registry keeps one `SessionMemory` per process, keyed by
`<toolName>:last_outcome`. A second call to `assess_requirement_quality`
in the same running server process can read the prior call's outcome —
this only holds within one running `stdio` process (one Workspace), not
across restarts.

## 5. Usage — remote Streamable HTTP MCP server (shared/team profile, dev only)

For exercising the real signed-OIDC identity path instead of the fixture
verifier:

```sh
npm run build
node dist/src/mcp/remote-dev-entrypoint.js
```

- Listens on `http://127.0.0.1:8787/mcp` by default.
- Override with `QA_INTELLIGENCE_DEV_REMOTE_PORT` / `QA_INTELLIGENCE_DEV_REMOTE_HOST`.
- On startup it prints a real, signed demo bearer token to **stderr**.
- Copy `hosts/cursor/mcp-remote.json.example` into your Cursor MCP
  settings, paste the printed token into its `Authorization` header, and
  connect.

This is still non-production: the membership store is a single-actor
in-process fixture, and production enablement is blocked on GOV-012
G1–G4 regardless of transport.

## 6. What's deliberately not covered here

- **API**: `api/README.md` — "Not started." No REST/GraphQL surface exists.
- **UI**: no UI package exists in this repo. All interaction today is
  through an MCP host's chat/tool-call interface as shown above.
- **Production auth (OIDC)**: ADR-014's production identity work is
  pending; both entrypoints above use dev-only fixture or self-signed
  identity, never a real IdP.
