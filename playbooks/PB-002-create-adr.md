# PB-002: Create an ADR

1. Confirm the issue is an architectural decision, not a requirement or implementation detail.
2. Search existing ADRs and conflicts.
3. Copy `templates/ADR.md`; use the next non-reused ID and `draft` status.
4. Record context, decision drivers, alternatives, consequences, risks, reversibility, owners, and affected specs.
5. Perform impact analysis and specialist review.
6. Record approval, update decision graph/indexes, and create downstream specification work.

An ADR explains why; it SHALL NOT become an implementation manual.
